Как три решения меняют политику

Разбор к защите. Дрон смещается по одной оси под действием ветра. За три шага мы проследим, что запоминает LSTM, как оценивается каждое решение и как меняются веса после одного обновления.

Что учится предсказывать агент

У квадрокоптера наблюдаемы положение, скорость и ориентация. Ветер скрыт. Наклон и дрейф на нескольких последовательных кадрах дают информацию о возмущении. Рекуррентный актор превращает историю в распределение команд. Критик оценивает ожидаемую сумму будущих наград с дисконтом.

Память h, cКаждая сеть переносит своё состояние между решениями.
Два выходаАктор выдаёт среднее μ команды, критик — ценность V.

Зададим начальное отклонение x₀ = 0,4. Постоянный ветер w = +0,2 сносит аппарат вправо. Актор видит только x и выбирает непрерывную команду a. Эпизод заканчивается после третьего решения. Единицы величин в этом учебном симуляторе условные.

x′ = x + 0,2 · (a + w)r = 1 − |x′| − 0,05 · a²

Один проход через ячейку LSTM

Входные ворота i дозируют новую запись, ворота забывания f определяют долю прежнего содержимого c, выходные ворота o определяют наблюдаемую часть памяти h. Для ручного счёта фиксируем i = f = o = σ(0) = 0,5. Обучаем четыре скалярных параметра каждой сети. В полноразмерной модели обучаются также веса ворот.

gₜ = tanh(wₓ · xₜ + wₕ · hₜ₋₁)cₜ = 0,5 · cₜ₋₁ + 0,5 · gₜhₜ = 0,5 · tanh(cₜ)yₜ = k · hₜ + b

У актора (wₓ, wₕ, k, b) = (1, 0,5, −0,8, 0,05), у критика — (0,5, 0,3, −0,6, 0,2). В начале эпизода h и c обеих сетей равны нулю. Для актора g₀ = tanh(0,4) ≈ 0,37995, c₀ ≈ 0,18997, h₀ ≈ 0,09386, поэтому μ₀ ≈ −0,0251. При следующем решении h₀ и c₀ войдут в формулы вместе с новым наблюдением.

Собираем один эпизод

Актор задаёт нормальное распределение со средним μ и стандартным отклонением 0,3. Для каждой команды берём a = μ + 0,3z, где z — выборка из стандартного нормального распределения. Генератор PyTorch на CPU с сидом 7 воспроизводит приведённые числа. Параметры сети фиксированы до завершения сбора.

Считаем, какие решения подкрепить

Критик сначала прогнозировал V₀ ≈ 0,1705. После получения r₀ и нового прогноза V₁ можно оценить ошибку первого предсказания. GAE (generalized advantage estimation) объединяет такие ошибки в обратном порядке. γ = 0,99 задаёт дисконт, λ = 0,95 управляет вкладом более поздних ошибок.

δₜ = rₜ + γ Vₜ₊₁ − VₜAₜ = δₜ + γλ Aₜ₊₁Rₜ = Aₜ + Vₜ

После настоящего терминального перехода V₃ = A₃ = 0. Если сбор оборвался посреди продолжающегося эпизода, в последнюю δ подставляют прогноз критика для следующего состояния. На границе нового эпизода рекурсия GAE прерывается.

δ₂ ≈ 0,4243 − 0,1367 = 0,2876 → A₂ ≈ 0,2876δ₁ ≈ 0,4997 + 0,99 · 0,1367 − 0,1520 ≈ 0,4831A₁ ≈ 0,4831 + 0,9405 · 0,2876 ≈ 0,7535A₀ ≈ 0,5536 + 0,9405 · 0,7535 ≈ 1,2623

Собираем функцию потерь PPO

Повторяем записанные наблюдения по порядку, начиная с тех же состояний памяти. Берём те же действия и сравниваем, какую плотность им назначают текущая и старая политики. В развёрнутой сети градиент позднего прогноза проходит через более ранние состояния LSTM.

qₜ = exp(log πnew(aₜ | hₜ) − log πold(aₜ | hₜold))sₜ = min(qₜ Âₜ, clip(qₜ, 0,8, 1,2) Âₜ)Lπ = −mean(s)   ·   LV = mean((V − R)²)L = Lπ + 0,5 LV

В начале первого обновления q₀ = q₁ = q₂ = 1. Среднее нормированных преимуществ равно нулю, поэтому Lπ ≈ 0. Однако при изменении весов каждый q изменяется по-своему. Это даёт ненулевой градиент. Из трёх ошибок критика получаем LV = 0,747962. Полная функция потерь равна 0,373981.

Меняем параметры один раз

В учебном примере используем SGD с η = 0,10. PyTorch вычисляет градиенты по всем восьми обучаемым параметрам. Для смещения b актора можно сверить производную вручную. При q = 1 производная логарифма гауссовой плотности по b равна (a − μ) / σ². Из-за знака в функции потерь перед средним стоит минус.

∂L/∂bπ = −mean(Âₜ · (aₜ − μₜ) / 0,3²) ≈ 1,22729b′π = 0,05000 − 0,10 · 1,22729 ≈ −0,07273

Прогноз критика поднимается с 0,1705 до 0,2478 в сторону цели 1,4328. По этому минибатчу ошибка критика уменьшается до 0,634905, общая функция потерь — до 0,258609. Чтобы судить о качестве управления, обученную модель оценивают в отдельных эпизодах.

Где срабатывает отсечение

Уже после обновления, без второго шага оптимизатора, снова вычислим вклад записанной команды в цель PPO. На t = 2 плотность команды упала до q = 0,6074 от прежней. При отрицательном Â дальнейшее уменьшение q увеличило бы выигрыш этой строки. Отсечение ограничивает выигрыш значением на q = 0,8.

Прямой вклад ≈ 0,6074 · (−0,9851) = −0,5983Отсечённый вклад ≈ 0,8 · (−0,9851) = −0,7880PPO выбирает min(−0,5983, −0,7880) = −0,7880

Проверьте отсечение сами

Положительное Â ограничивает награду за рост плотности выше 1,2. Отрицательное Â ограничивает награду за её снижение ниже 0,8. Штраф за изменение в невыгодную сторону сохраняется. Значение q после обновления может выйти за интервал. Ограничение применяется к функции цели.

Как этот шаг устроен в проекте

  • Вход актора содержит 22 числа: ошибку положения, скорость, матрицу ориентации, угловые скорости и предыдущую команду. Критик получает ещё 13 признаков симулятора, включая истинные ветер и массу. У актора и критика отдельные LSTM по 128 элементов.
  • За одно решение на частоте 50 Гц актор задаёт четыре компоненты: суммарную тягу, крен, тангаж и скорость рыскания. Для четырёх независимых компонент логарифмы условных плотностей суммируются. На демонстрации используется детерминированная команда политики.
  • Один цикл сбора содержит 16 сред × 512 шагов = 8192 перехода. Обучение повторно использует эти данные пять эпох, номинальный размер минибатча 4096. Состояния сохраняются в начале фрагментов. Внутри фрагмента порядок шагов сохраняется, добавленные при выравнивании позиции маскируются.
  • γ = 0,99, λ = 0,95, ε = 0,2, коэффициент ошибки критика 0,5. Используется Adam, начальная скорость обучения 0,0003 с линейным спадом, ограничение нормы градиента 0,5. Обучаются дисперсии действий через логарифмы стандартных отклонений, наблюдения и награды нормируются. В демонстрационном расчёте использованы фиксированное σ и один шаг SGD.

quadwind/training.py собирает тренер SB3-Contrib RecurrentPPO. quadwind/asymmetric.py разделяет признаки актора и критика. quadwind/fast_lstm.py реализует быстрый проход по последовательности с корректным сбросом памяти.

Почему нужен порядок наблюдений?

Логарифм плотности действия зависит от состояния памяти. Если перемешать шаги и обнулить память перед каждым, сеть получит другой контекст, изменятся значения q и направление градиента.

Обновляется ли сеть на каждом кадре видео?

Во время полёта меняются h и c. Обучение обновляет веса оптимизатором после сбора переходов. В полётной демонстрации используется сохранённая политика с фиксированными весами.

Почему на первом шаге q = 1, но актор всё же учится?

Равенство верно в начальной точке параметров. Производная log π по параметрам в ней обычно ненулевая. При одном и том же изменении смещения актора три действия меняют плотность в разной мере.
