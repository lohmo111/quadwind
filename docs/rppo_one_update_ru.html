Что знает агент

В Quadwind квадрокоптеру нужно удержать заданную точку. Актор видит отклонение, скорость, ориентацию и предыдущую команду. Несколько измерений подряд показывают, продолжается ли снос после коррекции. Память LSTM позволяет учитывать эту историю при выборе следующей команды. Критик во время обучения получает также истинный ветер и другие параметры симулятора.

В ноутбуке оставлена одна ось. Актор наблюдает отклонение x, а критик получает пару (x, w), где w — постоянный ветер. Для каждого наблюдения актор выдаёт среднее гауссовой команды μ. Критик выдаёт V — прогноз дисконтированной суммы будущих наград.

Память критикаИз x, w и своей предыдущей памяти критик вычисляет V.

Первый замер x = 0,4. Ветер добавляет +0,2. Среда ограничивает команду по модулю единицей и завершает задачу сразу после третьей награды. Индексы t = 1, 2, 3 совпадают со строками ноутбука.

Первый кадр вручную

Для учебной сети начальные веса и смещения входных ворот, ворот забывания и выходных ворот равны нулю. Поэтому в данном проходе каждые ворота дают σ(0) = 0,5. При обновлении все эти параметры доступны оптимизатору. Актор использует одну ячейку с кандидатом g.

gₜ = tanh(xₜ + 0,5 hₜ₋₁)cₜ = 0,5 cₜ₋₁ + 0,5 gₜhₜ = 0,5 tanh(cₜ)μₜ = −0,5 hₜ + 0,02

При нулевой начальной памяти c₁ = 0,5 · tanh(0,4) ≈ 0,18997 и h₁ ≈ 0,09386. Среднее первой команды μ₁ ≈ −0,02693. У критика в аргумент tanh дополнительно входит 0,5w, а прогноз равен Vₜ = 0,8hₜV + 0,1.

Считаем преимущество от конца к началу

Критик сравнивает свой прогноз с наградой и дисконтированной оценкой следующего состояния. Разность δ — ошибка прогноза на одном переходе. GAE объединяет её с последующими ошибками того же эпизода. В формулах ниже A — исходное преимущество, R — цель для критика.

Какое изменение выгодно актору

Снова подаём записанные наблюдения в прежнем порядке с той же начальной памятью. Для каждого сохранённого действия находим отношение плотностей q. Старые log π, преимущества и цели на этом минибатче фиксированы. Для актора используем нормированное преимущество Â. Для цели критика оставляем исходное A.

Перед первым обновлением q = 1, потому что траекторию воспроизвели при тех же параметрах. Среднее нормированное преимущество равно нулю и Lπ близка к нулю. Её производная при этом может быть ненулевой. Одно и то же изменение среднего μ по-разному влияет на плотности трёх записанных команд.

По трём строкам LV ≈ 0,626598. Так как Lπ ≈ 0 и коэффициент ошибки критика равен 0,5, общая потеря перед обновлением равна 0,313299.

Сверяем один параметр после шага Adam

В ноутбуке выполняется один вызов оптимизатора из тренера проекта. Градиент по совокупной функции потерь проходит через обе сети и через время внутри последовательности. Перед обновлением тренер ограничивает общую норму градиентов.

Проверим выходной вес Wπ актора в уравнении μₜ = Wπhₜ + bπ. Когда q = 1, производная логарифма гауссовой плотности по Wπ равна (aₜ − μₜ)hₜ / σ². Подставим действия, средние и скрытые состояния из таблицы.

gисх = −mean(Âₜ (aₜ − μₜ) hₜ / σ²)gисх ≈ (0,038262 + 0,014528 + 0,499953) / 3 ≈ 0,184248Общая норма всех градиентов ≈ 1,287316. После ограничения до 0,5 получаем g ≈ 0,071563 для этого веса.

Это первый шаг Adam, начальные моменты равны нулю. После поправки на смещение первый момент равен g, второй — g². В учебном примере η = 0,08, чтобы разницу было видно в таблице, а εAdam = 10⁻⁵.

W′π = Wπ − η · g / (|g| + εAdam)W′π ≈ −0,500000 − 0,08 · 0,071563 / (0,071563 + 0,00001) ≈ −0,579989

Выходной вес в сети после optimizer_step совпал с ручным прогнозом. Оптимизатор в тот же момент обновил и остальные обучаемые параметры. Заново пропустим через обе сети ту же последовательность.

Проверяем, когда действует clipping

После изменения весов подставляем в обе политики те же действия. При положительном Â рост плотности выгоден, но выше q = 1,2 дальнейший рост уже не увеличивает вклад этого перехода. При отрицательном Â полезно уменьшать плотность, и ниже q = 0,8 выигрыш перестаёт расти. Выход q за границу в противоположном направлении всё ещё может уменьшить цель.

На третьем решении при новых весах отношение q₃ ≈ 0,5362. Для записанной команды с отрицательным Â₃ ≈ −0,9769 считаем оба возможных вклада.

q₃ · Â₃ ≈ 0,5362 · (−0,9769) ≈ −0,5239clip(q₃) · Â₃ ≈ 0,8 · (−0,9769) ≈ −0,7815s₃ = min(−0,5239, −0,7815) ≈ −0,7815

Это фактический q после единственного обновления. Повторный проход только измеряет цель. Ограничение применяется к вкладу в неё, поэтому само q может оказаться за границами.

Где найти этот расчёт в проекте

  • native_rollout.py собирает переходы, вычисляет GAE и формирует последовательности для обновления. Минибатч переносит начальные состояния LSTM, хранит порядок кадров и помечает дополнение коротких фрагментов маской. Эти позиции исключаются из средних.
  • native_policy.py задаёт раздельные LSTM актора и критика, гауссово распределение команд, целевую функцию PPO и шаг оптимизатора. В полётной модели 22 входа актора, ещё 13 признаков у критика и по 128 скрытых элементов в каждой LSTM. Для четырёх команд складываются логарифмы четырёх условных плотностей.
  • native_training.py связывает сбор с повторными обновлениями. По конфигурации полёта и её базовым параметрам один цикл содержит 16 сред × 512 решений = 8192 перехода. Оптимизатор повторно обрабатывает данные пять эпох, на минибатч выделяется до 4096 позиций вместе с дополнением. Начальная скорость обучения Adam равна 0,0003.

Сохранённые полётные результаты в runs/e7 получены тренером SB3-Contrib. Ноутбук показывает обновление собственной реализации. Для новой реализации качество полёта проверяется отдельным обучением и оценкой на тех же условиях.

Почему сохраняем порядок наблюдений?

Плотность команды зависит от состояния LSTM. После перестановки кадров или сброса памяти перед каждым шагом актор получит другую историю. Даже без изменения весов плотность при повторном проходе может отличаться от сохранённой.

Что меняется между кадрами полёта?

Во время демонстрации сеть пересчитывает h и c после каждого наблюдения. Веса меняются во время обучения на собранных последовательностях. В начале нового полёта память сбрасывается, а выученные параметры сохраняются.

Какая часть написана в проекте и для чего нужен PyTorch?

Код проекта задаёт сбор траекторий, обработку границ эпизодов, GAE, последовательные минибатчи, формулы потерь и цикл обновления. PyTorch предоставляет LSTM, тензорные операции, автоматическое дифференцирование и Adam. Готовые исторические модели можно запускать через установленный SB3-Contrib.
