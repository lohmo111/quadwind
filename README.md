# Quadwind · Recurrent PPO for quadrotor hover

Team 8 trains a recurrent policy to hold a simulated Crazyflie at a fixed position while wind, mass, motor efficiency, measurement noise and delays vary. The actor infers useful control corrections from successive measurements. The wind and true vehicle parameters are hidden from the actor.

## One PPO-LSTM update in the notebook

Open [the executed notebook](notebook/rppo_one_update.ipynb) and run it from top to bottom. It first loads two saved checkpoints from the **same native training run** (`runs/native_defense/rppo_hover/seed_0`) — the early policy at **8,192 steps** and the validation-selected policy at **3M steps** — and flies both from the same start, seed and wind (the same `research/probe` condition as [the paired video](results/native_defense/before_after.mp4)). The early agent crosses the 2 m crash threshold at 3.46 s; the selected one completes the 15 s flight 1.33 cm from the target. Two wind scenarios follow: the existing `step_gust` and the new `ramp_gust` (0 → 3 m/s over 3 s), each plotted with wind speed and position error on a shared time axis, with peak deviation, recovery time (≤ 5 cm for a full second) and residual error reported. Then follow one action through three recorded transitions: what did the LSTM remember, was the reward better than the critic expected, and how did one Adam step change the action's density and the critic's prediction? The notebook calls the same rollout, loss and update functions as the native trainer, and only reads local checkpoints, CSV files and the MP4 — no training is launched when it opens.

| Where to look | What to explain |
|---|---|
| [Trajectory collection and GAE](quadwind/native_rollout.py) | Store each action, its old log-density and pre-action memory. Work backwards from rewards to advantages and value targets. |
| [Actor, critic and PPO loss](quadwind/native_policy.py) | Replay the recorded actions in time order, compare new and old densities, then differentiate the policy and value losses. |
| [Training loop](quadwind/native_training.py) | Collect fresh flights, run several epochs of updates on that rollout and validate the resulting policy. |

PyTorch supplies the LSTM layers, Gaussian distributions, automatic differentiation and Adam. The native trainer implements the recurrent PPO algorithm. The flight simulator uses SB3's vector-environment interface and its observation and reward normalization. The original live demo and `demo/hover.mp4` use a checkpoint from the earlier SB3-Contrib experiment.

## Native PPO-LSTM before and after training

Each of three seeds trained for 3 million transitions. In the paired recording, the early policy (8,192 transitions) crosses the 2 m crash threshold at 3.46 s. The validation-selected policy (3 million transitions) completes the same 15 s flight and finishes 1.33 cm from the target. Both use the same initial state, wind and sensor noise. [Paired flight video](results/native_defense/before_after.mp4) · [Validation curves](results/native_defense/validation.png)

On the same 200 held-out episodes, median 3D position RMSE was **2.12, 2.22 and 2.09 cm** for native seeds 0, 1 and 2, compared with **2.49 cm** for tuned PID. Each of the four controllers finished the separate 1,000-episode safety suite with zero observed crashes. [Native training report and per-seed results](results/native_defense/summary.md)

## How the flight policy was trained

- **Environment.** The rigid-body simulator advances at 500 Hz. Every 20 ms the policy chooses four continuous commands for collective thrust, roll, pitch and yaw rate. Each episode lasts up to 15 seconds. Position error, motion, tilt and control effort shape the reward. A crash ends the episode with a reward of −50.
- **Information.** The actor receives 22 normalized features per frame, including the previous command. Actor and critic have separate 128-unit LSTMs. During training the critic also receives 13 simulator features, such as true wind and mass. During inference only the actor chooses actions. The demo reuses its hidden and cell states on each decision and resets them at episode boundaries.
- **Optimization.** Sixteen environments collect 512 decisions each per rollout (8,192 transitions). Recurrent PPO uses GAE with γ = 0.99 and λ = 0.95, ratio clipping at 0.2, batches of 4,096 transitions and five optimization epochs per rollout. Both heads use two 128-unit tanh layers. Adam starts at 0.0003 with linear decay. The curriculum reaches full difficulty at 30% of the step budget.
- **Model selection.** Each of three independent training seeds had a budget of 3 million transitions. The library finishes the last rollout, giving 3,006,464 transitions. A separate validation set of 256 episodes was evaluated every 250,000 transitions. We kept the checkpoint with the smallest mean position RMSE, assigning a crashed episode a 2 m error. The demo uses seed 0; its selected checkpoint was at 2.5 million transitions.
- **Implementation of the packaged runs.** The original experiments used `sb3_contrib.RecurrentPPO` with the project's simulator, asymmetric actor-critic, recurrent sequence processing and evaluation protocol.

## Historical SB3-Contrib flight results

The three trained policies and the tuned PID controller used identical sampled conditions, the same attitude command interface and the same inner PI loop. The `final` namespace generated fresh conditions and noise seeds after the models and gains were chosen. These results describe the simulated distribution.

| Controller | Median position RMSE on 200 test episodes | Crashes on a separate 1,000 episodes |
|---|---:|---:|
| SB3-Contrib RPPO, seed 0 (demo) | 2.36 cm | 0 / 1,000 |
| SB3-Contrib RPPO, seed 1 | 2.37 cm | 0 / 1,000 |
| SB3-Contrib RPPO, seed 2 | 2.67 cm | 0 / 1,000 |
| Tuned PID | 2.49 cm | 0 / 1,000 |

RMSE is the root mean square of the 3D position error from 2 seconds onward. The table reports the median across surviving episodes. RPPO achieved centimetre-scale hover comparable to PID here. Zero observed crashes gives a two-sided 95% Wilson upper limit of about 0.38% **per controller** for the 1,000-episode suite. All controllers faced the same 1,000 conditions. This experiment measures simulated hover; the contribution of memory alone requires a matched ablation.

## Reproduce the experiment

With the project environment active, this test runs two short native rollouts in the hover simulator and reloads the checkpoints from a temporary folder.

```bash
python -m pytest tests/test_native_training.py::test_native_hover_train_validate_and_reload
```

For a full native experiment, run the three training seeds and evaluate their selected checkpoints alongside the tuned PID. Each seed gets 3 million transitions. The first command keeps the reproduction in its own experiment folder.

```bash
python scripts/run_series.py --configs configs/rppo_hover.yaml --backend native --exp native_reproduction --seeds 0 1 2 --parallel 3 --threads 2
python scripts/evaluate.py --runs "runs/native_reproduction/rppo_hover/seed_*" --which best --suites test_id safety --namespace final --baselines pid --out results/native_reproduction/episodes.csv
python scripts/summarize_hover.py --csv results/native_reproduction/episodes.csv
```

The flight models in `runs/e7` are ready to evaluate. To reproduce the earlier SB3-Contrib experiment, select its backend explicitly. One historical training run took about 40 minutes on the team's CPU.

```bash
python scripts/train.py --config configs/rppo_hover.yaml --backend sb3 --exp reproduction --seed 0 --threads 2
python scripts/evaluate.py --runs "runs/e7/rppo__pi__safe__att__asym__hp_epochs5__hp_lstm128/seed_*" --baselines pid --suites test_id safety --namespace final --out results/reproduction/episodes.csv
python scripts/summarize_hover.py --csv results/reproduction/episodes.csv --out results/reproduction/summary.csv
python -m pytest
```

To submit your own recording, run the following after exporting it as MP4. The command builds `submission/Quadwind_RPPO.zip` with that video, slides, notebook, explainer, code and checkpoints. The completed native experiment adds its paired video, validation curves, per-episode data and the three seeds’ initial, early and best checkpoints with their observation statistics.

```bash
python scripts/package_submission.py --video my_flight.mp4
```
